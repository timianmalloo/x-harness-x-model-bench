## 2. The marker split: the strict-xfail narrowing rule

**Rule.** A strict-xfail marker over a parametrised test may be narrowed to exactly the parameter ids observed failing on the same commit, and only that way:
1. the narrowed marks stay `strict=True` with the same reason text;
2. nothing is made non-strict, widened, reworded or skipped;
3. the observed run (failing and passing node ids, from a file) goes in the commit message;
4. the narrowing is its own commit, before any correction to the remaining parameters, so the join can replay it.

**Why it loosens nothing:** every parameter that already passes then runs as a real test, and a narrowed parameter that passes early still fails strict. It replaces the K1c compile's "never a marker split" for this case (MARK-B). Applied as F1: `test_window`'s marker moves to `pytest.param` marks on W4c, W10a, W10b and W10c; after F1 the runtime group has 0 failed and 0 XPASS, so every later commit of the finishing turn is green.
