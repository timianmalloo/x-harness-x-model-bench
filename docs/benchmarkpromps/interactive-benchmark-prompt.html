Interactive run: one CLI session per arm, the way a developer works

Two windows of the same CLI: one in a pack-on folder, one in a pack-off folder. Each gets the same single paste and works through the 11 lean tasks one at a time, as one long developer session. Nothing is launched headless. Afterwards the bench grades each task folder with its own graders and reads each session's own record for tokens and tool calls. The headless run (lean-benchmark-run-prompt.html) stays as the automated alternative.

1. Prepare the two folders (once per CLI and model)

In any PowerShell window:

cd C:\Projects\x-harness-x-model-bench
uv run bench interactive prepare --harness HARNESS --tasks S1,S2,RS1,RS2,RW1,RW2,NG1,NG2,SM1,SM2,SV1 --pack C:/Projects/ai-forward@0900e784594a2ce27d5110ca5b24ad170e5dbf7e

HARNESS is claude-code, codex, copilot or agy. It prints two folders, C:\Projects\bench-interactive\int-HARNESS-<UTC time>\off and …\on. Each holds the 11 task folders (base trees only; the hidden tests stay in the bench) and .bench\next.py, which hands out one task at a time. on also has the AI-Forward pack (revision 102) installed at its root; off holds no instruction file (prepare checks). For a second model of the same CLI (Copilot with gpt-5.5, say), prepare another run.

3. While it runs

  • Leave both windows alone. Expect 1 to 4 hours: 11 tasks, two of them in two turns (13 hand-outs).
  • If a session stops early and asks you something, answer continue. The report counts what finished; an unfinished task is graded on what is in its folder.
  • When it prints ALL DONE, exit the CLI (/exit, or Ctrl+C twice) so it writes the end of its record. Copilot writes its token totals only when the session ends.

What the report can and cannot say

  • Graded the same way as a headless cell. Pass/fail and each property check come from the bench's own graders. Each task folder is replayed onto a fresh copy of its base tree, the path bench discriminate uses; the two-turn tasks are graded on the turn-1 snapshot next.py takes. The catalog's process metrics need a record per task and are not graded here.
  • Tokens and tool calls per task come from each session's record, split at the next.py calls. Copilot records usage only as a total when the session ends, so it shows session totals and no per-task tokens. agy is read from its conversation database (field map checked against 1,542 requests).
  • One session per arm, with the tasks in the same fixed order in both arms. Context carries from task to task, as in real use. That is why this mode is not comparable with the headless runs.
  • A deleted file cannot be replayed, and the report lists any. So does a session that read the queue file directly or never reached a task.
