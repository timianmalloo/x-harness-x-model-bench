Prompt 2: analyse the lean runs

Paste into one CLI session in C:\Projects\x-harness-x-model-bench (full permissions). Nothing to fill in: it finds every finished lean run itself, checks it, and writes four pages: run health and issues, behaviour (drift, ceremony, over-thinking), cost, and pack-on vs pack-off. Model judges are off unless you switch them on.

How to use it

  1. Paste it whenever you like. Runs still going are listed as pending and left out; paste again later to add them. To limit it to some runs, paste their HANDOFF: lines under RUNS.
  2. To also grade with the model judges, change JUDGE = no to JUDGE = yes. Judging costs tokens and needs BENCH_OPERATOR_EMAIL.
  3. It ends with the four pages open in Chrome and committed locally (not pushed).

The four pages

PageAnswersFrom
1. Run health and issuesWhich runs and cells count? What went wrong, and whose fault (prompt, bench, harness, environment)?bench status --json, verify, each handoff.json "issues", each CLI session transcript
2. BehaviourDrift, ceremony, over-thinking per harness and arm; the same model in two harnesses; the interactive CLI sessionstools/behaviour_measures.py over the runs' facts and the session transcripts
3. CostWhat drives each harness's tokens and wall time bench report --cost-compare
4. Pack on vs offWhere the pack's extra cost goes, where it pays off, tuning candidates bench report --pack-cost and the pack at its pinned revision
Runs are never copied. A run is reached through a directory junction in C:\Projects\bench-runs-index\<REPORT_ID>. A junction is removed only with cmd /c rmdir, never a recursive delete, which would delete the run it points to.

The prompt

Analyse the lean benchmark runs made by Prompt 1 and write four pages. Work alone in the main checkout,
C:\Projects\x-harness-x-model-bench: no sub-agents, no coordination layer, no new worktree. Use `python`, never
`python3` (Windows). Tokens are the only cost unit; never write USD. Never print a token or credential. Do these
steps and nothing else; report each step in one line.

SETTINGS (change only by editing the prompt):
  JUDGE    = no    (yes: also grade with the model judges, STEP 3; costs tokens)
  RUNS     = all   (or paste HANDOFF lines here, one per line, to limit the set)
  PACK_GIT = C:/Projects/ai-forward

GOAL: four pages under docs/benchmark-reports/<REPORT_ID>/, open in Chrome and committed locally: (1) run health
and issues, (2) behaviour, (3) cost, (4) pack on vs off. DONE WHEN: every ready run passes `bench verify`, the pages
exist and are open, and they are committed. NOT IN SCOPE: running cells, editing bench code or the pack, changing a
grade by hand, pushing, deleting any worktree or run.

STEP 0 - start state (stop and report if a check fails)
  - `git pull --ff-only origin main` succeeds (local changes that block it are a stop; never stash or reset them).
    Record `git rev-parse HEAD` as BASE.
  - REPORT_ID = report-<UTC yyyymmddThhmm>. OUT = docs/benchmark-reports/<REPORT_ID>.
    INDEX = C:\Projects\bench-runs-index\<REPORT_ID> (a folder of junctions, one per run).
  - Unset XAI_API_KEY. If JUDGE = yes: BENCH_OPERATOR_EMAIL is set (check non-empty; never print it), and
    HB_CLAUDE_OAUTH_TOKEN = the contents of C:\Users\malla\.harness-bench\claude-oauth-token.txt.txt, whitespace
    stripped, in the environment of `bench grade` only; then `uv run bench tools install`.

STEP 1 - find and check the runs
  - Candidates: every C:\Projects\x-harness-x-model-bench-bench-lean-*\runs\<RUN_ID>\ folder (or only the pasted
    HANDOFF lines). For each, with WT = its worktree and CELLS = C:\Projects\bench-cells\<RUN_ID>:
      * `uv run bench --runs <WT>\runs --cells-root <CELLS> status <RUN_ID> --json`
      * READY when it is not running, every cell has ended, and its grading pass completed (validity is not "not
        graded"). LIVE when a cell is still running: list it as pending, leave it out. Anything else is BROKEN: say why.
      * READY only: `uv run bench --runs <WT>\runs verify <RUN_ID>` exits 0 (exit 5 is an integrity failure: the
        run becomes BROKEN; never repair it).
      * Read <WT>\runs\<RUN_ID>\handoff.json if it exists (combo, settings, validity, issues, session_id,
        transcript). A run with no handoff.json is still READY if the checks pass; note "no handoff.json".
  - Print one table: run, harness, model, effort, context, state (READY / LIVE / BROKEN), cells ended, valid cells,
    validity counts by code, handoff.json yes/no.

STEP 2 - the index (READY runs)
  - For each: `New-Item -ItemType Junction -Path <INDEX>\<RUN_ID> -Target <WT>\runs\<RUN_ID>`, then
    `uv run bench --runs <INDEX> verify <RUN_ID>` exits 0. If a bench command refuses a junction, use
    `robocopy <WT>\runs\<RUN_ID> <INDEX>\<RUN_ID> /E /COPY:DAT /R:1 /W:1 /NP /NFL /NDL` for that run instead
    (exit 0-7 is success) and say so. Every later bench command uses `--runs <INDEX>`.

STEP 3 - judges (only if JUDGE = yes; otherwise print "not judged" and go on)
  - Per READY run: `uv run bench --runs <INDEX> --cells-root C:\Projects\bench-cells\<REPORT_ID> grade <RUN_ID>
    --allow-model-calls`. Record "graded N cell(s) in pass <grading_id>"; N must equal the run's cells. A refusal is
    reported verbatim. Then `verify` again: exit 0.

STEP 4 - page 1, run health and issues
  - Per READY run: `uv run bench --runs <INDEX> report <RUN_ID>` (writes its report.html); a refusal is quoted.
  - The issues: every handoff.json "issues" line; every invalid cell (code and text, from status --json); every
    LIVE or BROKEN run; and the CLI sessions' own problems: for each run's transcript (handoff.json "transcript";
    if "not found", search the CLI's session store for the RUN_ID), list errors, refusals, retries, workarounds and
    deviations from Prompt 1, each with a locator (line or timestamp).
  - Write OUT/run-health.md: the STEP 1 table; then one row per issue: id, run, step, what happened (quote at most
    25 words), locator, cause (prompt / bench / harness / environment / model), and the fix it needs. Every number
    comes from bench output; label any number you computed as computed.
  - `python docs/ai-forward-pack/scripts/render-markdown.py OUT/run-health.md --open`

STEP 5 - page 2, behaviour (drift, ceremony, over-thinking)
  - `uv run python tools/behaviour_measures.py --run <INDEX>\<RUN_ID> [--run ...]
     --session <RUN_ID>=<harness>:<transcript> [--session ...] --out OUT/behaviour`
    (one --session per run whose transcript was found; the harness name is the run's.)
  - Read OUT/behaviour/behaviour.md and the per-cell JSON. Write OUT/behaviour-analysis.md:
      * Over-thinking: requests, reasoning tokens and reasoning characters per cell, per harness and arm.
      * Ceremony: tool calls, calls before the first edit, reads, planning or to-do tool calls, files written outside
        the task (lines outside, machine lines), and, for the interactive sessions, status messages and poll cadence.
      * Drift: scope_creep, attention_drift, lines outside the blast radius, delegation tool calls.
      * The same model in two harnesses (for example gpt-6.1-sol in Codex and in Copilot): compare them task by task
        and arm by arm, and say whether the difference is in what was produced (output style) or in what was done
        (actions), with the numbers.
      * What the records cannot show, per harness (a measure the bench reports as "not recorded").
    Label each claim Verified (seen in a file; cite it) or Inferred (state the model and what would confirm it).
    Cells of a run with invalid cells are reported with that caveat, never silently pooled.
  - `python docs/ai-forward-pack/scripts/render-markdown.py OUT/behaviour-analysis.md --open`

STEP 6 - page 3, cost
  - `uv run bench --runs <INDEX> report --cost-compare <RUN_ID> ... --out OUT/cost-compare.html` (it needs
    BENCH_OPERATOR_EMAIL; if unset, say so and skip this page). Read its tables and the facts behind each difference
    (tokens by part, requests, prompt_parts, served settings, harness_events, wall time). Write
    OUT/cost-compare-analysis.md: per harness, what drives its cost, with root causes labelled Verified or Inferred,
    citing only numbers in the generated tables. Regenerate with `--analysis OUT/cost-compare-analysis.md --open`;
    a refusal lists numbers not in the tables: fix the analysis, never the tables.

STEP 7 - page 4, pack on vs off
  - `uv run bench --runs <INDEX> report --pack-cost <RUN_ID> ... --out OUT/pack-on-vs-off.html`. Read its tables
    and the pack at the run's pinned revision (`git -C PACK_GIT show <commit>:<path>`, never a checkout): the
    always-loaded files, the hooks each harness runs per tool call, the skills the cells invoked (harness_events).
  - Write OUT/pack-on-vs-off-analysis.md: (a) per harness, where the extra tokens and wall time come from, largest
    first, with the pack file or hook that causes each; (b) where the pack paid for itself and where it cost with no
    gain; (c) tuning candidates ranked by expected saving, each with the change, the evidence, the expected effect,
    the risk, and how a next run would measure it. Regenerate with `--analysis ... --open`.

STEP 8 - close
  - `git add OUT` and commit: "docs(benchmark): analysis <REPORT_ID>". Do not commit runs/. Do not push.
  - Leave INDEX, the worktrees and the runs in place. Never delete a junction with a recursive delete.
  - Report: the STEP 1 table, the four page paths, the commit, the pending (LIVE) runs, and anything that did not go
    as written.

Known caveats (say so in the pages where they apply):
  - Grok and agy run one cell at a time (a shared or rotating login); compare their wall time per cell, not per run.
  - Codex runs its reads and edits through shell commands; its read / edit classes and attention_drift are "not
    recorded" until its reader classifies shell commands.
  - The pack's hooks run before every tool call (several processes each); in Grok this costs seconds per call. Claude
    Code records only its Stop-hook time. Pack-on wall time includes this cost.
  - Interactive Copilot sessions write token usage only at session shutdown; an open session's tokens are "not
    recorded".
  - agy does not report its context window: "not recorded".
  - A run with fewer than 2 repetitions per cell has no spread; say so rather than draw a conclusion from one cell.
