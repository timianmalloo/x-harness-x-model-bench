### Conflict 1: the Data & Persistence Architect's lens

- **What decides it.** ADR-0006 line 55 says: "The canonical form is `json.dumps(…)`, with integers and strings only. No floats: a non-integer measure is a decimal string at the scale its catalog entry fixes." `ledger._check` (`ledger.py:41-45`, read on `3f887a0c`) refuses anything but str, int, None, list and dict, and `Engine.record` runs `ledger.canonical` first (`engine.py:238`). W1-J §4.1 types the field `float`, and §3, §4.2 and §10 store it. An ADR wins over a design (W0, *Authority order*), so the float is void. The worker's option (a), a finite-float exception in `_check`, is an ADR-0006 change. It is the Owner's, nobody asks for it, and it is not recommended.
- **Status check (not from memory).** ADR-0006's frontmatter says `status: draft`, and its body says "Proposed". No ADR in `docs/adr/` is `accepted` (`grep -c "status: accepted"`: 0 for all 21). The canonical form is still in force. It is built into `ledger.py` since phase 1, it has had five amendments ruled by the Owner (R-26, R-15, R-58, R-80, and the council for Amendment 5), and every ledger is written in it. I treat it as deciding. *Inferred:* the repo's ADR status field is not maintained. That is a finding for the Owner, not a ruling.
- **Grain.** One row is one returned turn of one cell (W1-J §2, unchanged).
- **Unit and measure class.** A duration in the ledger is always an int in ms. The evidence: `cell.outcome.turn_ms = int(result.turn_seconds * 1000)` (`engine.py:718`), `handshake_ms`, `last_update_ms`, `identity_check_ms` (`engine.py:573`), and `duration_ms` on the sibling `cell.turn_snapshot_archived` row (ADR-0006 Amendment 5). `turn_ms` is additive over the turns of a cell. Agent time is `Σ turn_ms` over the rows present, and a missing row is "not recorded", never 0.
- **Derive, don't store.** The outcome's `turn_ms` (the last turn's) already exists. With the same expression on the same float, `outcome.turn_ms == turn_ended{last}.turn_ms` exactly. A decimal-string `turn_seconds` would keep the ADR's field name, but it is refused. It would be the ledger's only string duration. Every sum would parse it. Its rounding (`f"{x:.3f}"` rounds) would differ from the outcome's truncation by up to 1 ms, which makes two definitions of one quantity (DM7).
- **History and migration.** No ledger holds a `turn_ended` row (`git grep turn_ended 8998d092 -- src`: exit 1). Nothing is migrated, rewritten or backfilled. The in-memory `TurnRecord.turn_seconds` float is unchanged.
- **What is not mine: the ADR texts.** ADR-0006 Amendment 5 (`:177`) and ADR-0015 (`:46`, `:64`) name the field `turn_seconds`, with no type. Renaming it in an ADR is not a Coordinator's edit. **Decision request `req-01M46PAJGJEEE7GBDV7YXVHC4T`** went to `owner-fable` (mail `mail-01M46PAJGTH87Q2H6SEDAWJ0JQ`). It carries three options (ratify `turn_ms`; keep `turn_seconds` as a decimal string; a float exception), evidence, recommendation (a), reversibility, blast radius, a 24 h deadline and a fallback: (a) stands, and the next Coordinator that touches either ADR appends a one-line erratum. **I did not rule on the ADR text.** The DR does not block J1b. Its residual risk is that the Owner picks (b), and then J1b's K4(3) commit, T-ENG-11 and W1-J §15 change before the readers (A3c, J2c, K1) build.
