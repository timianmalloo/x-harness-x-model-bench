Context & Objectives

The Project Intent: Cutting Through Benchmark Anecdotes

Why x-harness-x-model-bench was conceived and what makes its construction methodology unique.

In the rapidly evolving landscape of AI-assisted software engineering, decisions about coding agents have historically been driven by anecdote, vibes, and surface-level marketing claims. Developers and tech leaders frequently debate:

  • "Does Claude Code outperform Codex CLI, or is it just the underlying model?"
  • "Does an instruction pack like AI-Forward improve architectural rigor, or does it merely burn context tokens?"
  • "How do agent harnesses behave when handling ambiguous requirements, multi-agent delegation, or formal verification?"

To answer these questions empirically, x-harness-x-model-bench was created. It executes a factorial matrix across harness × model × pack:

Comparison Held Fixed Varied Scientific Question
Harness Effect Model (e.g. GPT-6 Sol) Harness (Codex CLI vs Copilot CLI) How much of agent success is due to the CLI scaffolding vs the model?
Model Effect Harness Family Model (Opus 5.5 vs Sonnet 5 vs GPT-6 Sol) What capability tier is required for each lifecycle scenario?
Pack Effect Harness + Model AI-Forward Pack (ON vs OFF) Does systematic engineering discipline tangibly prevent defects?

The Meta-Achievement: The benchmark itself was developed by dogfooding the very discipline under test. The author operated as Chief Architect and System Controller, orchestrating an AI-Forward multi-agent organisation across 64 sessions to take the system from a raw proposal document to an airtight, cryptographically verified, fully tested codebase.

Philosophy & Mindset

The Paradigm Shift: From Chat Prompting to Agentic Systems Engineering

How professional AI-forward coding departs fundamentally from conversational code generation.

Conversational AI Coding (The "Vibes" Trap) Fragile
  • Single, unstructured chat conversations that degrade over time.
  • Prompts that jump straight into writing implementation code.
  • Relying on LLM memory and "plausible" assertions without checking.
  • Blindly accepting bloated architectural patterns suggested by the model.
  • Testing done by eyeballing output or asking the same LLM "did you test this?".
  • Bugs treated as random glitches, patched locally without structural prevention.
AI-Forward Systems Engineering Deterministic
  • Strict Layering: Spec → Architecture → Slices → Proof → Code.
  • Autonomous Seats: Human sets intent; Owner rules on invariants; Coordinator executes graphs; Workers build.
  • No Guessing Protocol (NG1–NG11): Spikes before contracts; marked assumptions; zero unverified claims.
  • The Human Simplicity Filter: Ruthlessly challenging model over-engineering (e.g. the ADR-0013 container drop).
  • Hard Verification Floors: 100% Red-First TDD, cosmic-ray/Stryker mutation testing, TLA+ formal models.
  • Defect-Class Institutionalization: Every bug produces an automated gate or hook so the shape never recurs.

"Autonomy is latitude in the how, never the what. A question is not a licence to author a change, and a gap found en route is a finding, never a new goal."

Architectural Mastery

The Great Pivot: Slashing Accidental Complexity

How the human operator saved weeks of maintenance by challenging model-driven over-engineering.

When asked to design an isolated benchmarking environment, AI agents initially defaulted to standard enterprise "best practice": wrap everything in Linux Docker containers, configure virtual networking, set up egress proxies, and route credentials through sidecar containers.

In Prompt #5, the user intervened: "lets step back - why do we actually even need docker and containers? Our current coordination model allows us to spawn CLI instances without that. We don't need extra isolation."

ADR-0001: The Container Maze Rejected
  • Docker Desktop & WSL2 mandatory on host.
  • WSL2 memory leaks causing exit 137 OOM kills.
  • Bind-mount filesystem latency degrading Python runs.
  • Docker socket isolation & egress proxy configuration.
  • Windows credential store inaccessible; GitHub Copilot required a dedicated personal access token.
  • Clock skew between host and virtual machine.
ADR-0013: Native Cells + Job Objects Adopted
  • Zero Docker dependencies: Runs natively on Windows workstation.
  • Windows Job Objects: Instant process tree shutdown (active procs 2 → 0), peak memory tracking, and crash safety.
  • Local Git Clones (git clone --local): Hardlinked objects for instant cloning, but totally decoupled refs and stashes.
  • Native Credential Integration: Copilot uses Windows Credential Manager; zero tokens needed.
  • Measurement Validity Preserved: Per-cell config homes, pinned CLI builds, and clean ancestor paths.

Why not git worktree? The user originally suggested worktrees, but the architectural review caught a critical measurement leak: worktrees share git refs, configs, and stashes. An agent's commits in a pack=on branch would be visible in git log --all of a pack=off cell! The decision pivoted to git clone --local with the origin remote removed: instant file copying with absolute ref isolation.

The Cross-Vendor Adversarial Review Rule

A core failure mode in AI coding is sycophancy: an LLM reviewing its own code almost always approves it. To break this, the AI-Forward coordination layer enforced a mandatory cross-vendor review protocol at every join:

  • Codex Author → Claude Reviewer: Code authored by Codex (GPT-6 Sol) had its test failures and PRs reviewed by Claude Code (Opus 5.5).
  • Grok Author → Codex/Claude Reviewer: Work authored by Grok was reviewed by Codex or Claude.
  • The Test Architect Veto: A dedicated Test Architect persona (Claude Opus 5.5 / Fable) held an absolute veto. If an author could not prove a test was red before green, or failed to kill seeded mutants, the join was immediately blocked.
Verification

The Rigor Engine: Red-First TDD, Mutation Testing & Proof Packs

How mathematical proof and automated mutation testing eliminated regression bugs across 1,766 tests.

1. Non-Negotiable Red-First TDD

In this repository, an agent is never permitted to commit code and tests together. Every single bug fix and feature followed an immutable commit pair:

  1. RED Commit: The agent writes the test only. The coordinator checks out the commit in a separate throwaway worktree and verifies that the test fails on main for the exact expected reason.
  2. GREEN Commit: The agent writes the minimal implementation in src/. The test suite passes.
  3. Join Re-verification: The Leader re-executes the red commit and green commit to guarantee that no tests pass vacuously.

2. Mutation Testing (Cosmic-Ray & Stryker.NET)

Code coverage is a vanity metric; a suite can have 100% line coverage while asserting nothing. To enforce real semantic rigor:

  • Every major track created a mutation file (e.g. tests/mutations/engine.json, copilot.json, driver.json).
  • Cosmic-ray (Python) and Stryker.NET (C#) automatically mutated operators (inverting booleans, altering boundary checks, deleting calls).
  • Reviewers injected 3 custom mutants into each PR. If any mutant survived, the join failed.

3. Formal Proof Packs (docs/proof/phase1.md & phase2.md)

Releases did not end with a generic "looks good to me" PR description. Each milestone produced a formal Proof Pack:

Claim Confidence Verified Evidence Residual Risk
Walking Skeleton E2E Verified Real 4-cell E2E run (Claude Code & Codex, pack on/off); 4 outcomes valid; prompt hashes byte-identical. Single repetition per combo (n=1); model non-determinism.
Red-First Closure Verified Every finding across T1–T12 has cited red commit SHA verified failing on clean baseline. None; all SHAs re-executed in throwaway worktrees.
Codex Skill Leak (N5) Flagged Codex 0.156 loads host skills from USERPROFILE; disclosed in report header and xfail(strict). Codex-vs-Claude comparisons carry disclosed confound until Codex patch.
Defect Prevention

The Defect-to-Control Machine: Lessons Turned into Code

"A lesson recorded as prose is a memoir; it only counts once it is a test, a gate, or a hook."

Under the AI-Forward doctrine (CI1–CI12), when an error, bad assumption, or flakiness occurred, the team was prohibited from merely patching the one file. They executed: Class → Sweep → Derive → Prevent.

Defect Class Real Incident Observed Root Cause Permanent Machine Control Built
EDIT-B
Heredoc corruption		 Bash heredoc generated Python scripts with corrupted \n and escaped backslashes. Nested string generation in shells drops backslashes silently. Built tools/heredoc_guard.py: A PreToolUse hook in .claude/settings.json that hard-blocks any heredoc fed to Python (exit code 2).
MOD-A
Vacuous model tests		 Seeded TLA+ model bug variants showed "violated", but were failing due to unrelated invariants. TLC model checker stops on first violation, masking invariant independence. Built tools/check_models.py: Automatically tests each seeded variant against its isolated target invariant alone.
CONC-A
Check-then-act race		 Two parallel cells checked if a destination folder existed; both saw no and crashed on Windows os.replace. Non-atomic directory replacement on Windows filesystems. Refactored into workspace._land: Atomic directory creation with transient retry and barrier synchronization.
TOOL-A
Stale bytecode in mutations		 Mutation testing restored source code, but Python's cached .pyc had identical mtime, causing false kills. Python bytecode caching ignores sub-second restores of identical byte lengths. Enforced PYTHONDONTWRITEBYTECODE=1 and built byte-exact clean checks in mutate_check.py.
Playbook

The 6 Core Tenets: How to Apply This Approach

Actionable engineering principles for teams building complex systems with AI coding agents.

01
Ground in Real Artifacts First
Never start an agent session with an empty prompt asking for an application. Provide a visual mockup (HTML), a problem proposal, or an API schema. Concrete artifacts constrain the solution space and prevent hallucinated architectures.
02
Specify Before You Architect
Enforce a 3-layer specification (Functional, UX, UI) with testable acceptance criteria before writing a single line of architecture. If an agent cannot state the exact Gherkin Given/When/Then criteria, it does not know what to build.
03
Spike Before You Contract
Never assume an API, SDK, or tool behaves as documented. Run an empirical spike: write a 20-line scratch script, run it against the real system, observe the exit codes and logs, and label the finding Verified.
04
Challenge Architectural Bloat
LLMs tend to generate over-engineered architectures (e.g. unnecessary microservices, containers, or distributed queues). The human's highest-value role is stepping back and asking: "Why do we actually need this complexity?"
05
Never Let an LLM Grade Itself
Separate authoring from review. Use cross-vendor adversarial reviewers (Codex writes, Claude reviews) and automated mechanical oracles (Red-First tests, mutation testing, formal checkers) with veto power over PR merges.
06
Institutionalize Every Bug
Never fix a defect in isolation. Identify its failure class, sweep the codebase for siblings, and construct an automated hook or gate that fails immediately if the pattern ever recurs. Turn lessons into code, not memoirs.
