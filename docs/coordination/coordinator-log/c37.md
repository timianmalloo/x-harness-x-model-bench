Codex's `model_context_window` is 258,400, so nothing in the harness stops at our 200k. **About 110k went on grounding**, and only about 60k on K4(5) and its seams. So the rule bounds the reading first, then the work:

1. Sample the figure before each K-item, before each gate command, and before reading any file longer than 300 lines.
2. Reads are line ranges, never a whole design file. Gate output goes to a file, and only its summary is read.
3. No K-item starts above 120k.
4. **The hand-back point is after K3 (lifecycle).** K4 starts only if the sample there is at or below 110k. Otherwise K4 and the gates go to the follow-on by name.
5. At 170k, nothing new starts. The worker writes the closing entry and hands back.
6. If the figure cannot be read, it is recorded "not recorded", and the worker hands back at the K3 point.

The closing entry records the sample at each K-item, so the next split is sized from J1d's own record.

*Inferred (named gap):* how much one J1d K-item costs. J1c's K4(5) plus its seams cost about 60k. The thresholds give one K-item about 50k of headroom below 170k. If J1d's record shows a K-item above 50k, the thresholds move down.
