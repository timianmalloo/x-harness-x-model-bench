Verdict

The pack did not earn its cost in grid-1. It used 3.5× the tokens and 1.9× the wall clock and passed 40 of 54 cells against pack-off's 48 of 54. That gap is not significant pooled (p = 0.08). 10 of the 14 pack-on failures come from two pack behaviours, not from wrong code. In 7, the work went into a new git worktree the grader never saw (rule WT1). In 3, pack ceremony used up the turn before any code was written. Where the pack changed behaviour it did so as intended: a goal-state block in 51 of 54 cells, and tests written before code on D1 in 8 of 9. But no smoke task can show that this discipline pays off. The other intentions (security, privacy, compliance, resilience, the Spike Protocol, rework avoided) have no measurement at all in this BOM. So the rule the user set applies: the extra cost did not buy measurable rigor, so something must be fixed. The ranked fixes are in Where to improve.

How this was measured

  • Cells. grid-1 graded 84 of 108 cells: an OAuth expiry skipped 24 cc-opus cells. grid-1-cc re-ran all 36 cc-opus cells with the same cell ids, so its rows replace grid-1's 12 graded cc-opus rows. One of those rows (F1.cc-opus.pack-off.r1 in grid-1) had wall = 0 and failed. Result: 108 cells, n = 3 for every task × combo × arm.
  • Tokens are the sum of model_calls rows (uncached input + cache read + cache write + output). turn_usage undercounts: for Codex pack-on it shows about 65 k per cell against 1.3 M in model_calls, because it keeps one summed row per model. Copilot's record has session totals only, so per-call context for Copilot is NA.
  • Wall clock is turn_ms from each cell's cell.outcome event.
  • Quality is the graded scores/*.jsonl rows. Tests: two-sided Fisher exact on pass@1 counts, Holm-adjusted over the 6 tasks. Cost: the per-pair on/off ratio (pairs matched on combo and repetition), reported as the median and a count of pairs above 1.
  • Behaviour comes from each cell's transcript in archive/<cell>/attempt-1/home, in all three harness formats. The extractor counts tool calls that read pack files, load skills, call audit-log.py, docs-graph.py or coord-core.py, or create a worktree. It also detects goal-state blocks and the order of the first test-file write against the first source-file write. The first version of the test-first detector matched file contents as well as paths. A spot-check caught that, so the detector now reads only write-target paths. Every failure attributed below was confirmed in the grader's oracle.log and the archived tree.
  • grid-2 (BOM 0.5, 22 tasks, same pack r97) was still running and graded: false at 20:22Z. Only codex-sol ran in full; copilot-sol and cc-opus were skipped by login failures. It is excluded and named pending.

Findings

F-1 · The pack's cost is large and consistent VERIFIED

Token ratio on/off by harness: Codex 6.8×, Copilot 4.3×, Claude Code 1.6×. Wall ratio: 2.7×, 2.1×, 1.4×. Tool calls: 1,430 on vs 1,007 off. The median per-pair token ratio by task: A1 4.9, B1 11.5, C1 9.6, D1 3.4, E6 5.1, F1 1.3.

F-2 · Most of Claude Code's extra spend is fixed context; most of Codex's is extra calls VERIFIED + INFERRED

Median input on the first model call (n = 18 per arm): Claude Code 21.4 k → 39.9 k (+18.4 k); Codex 12.0 k → 21.1 k (+9.2 k). Copilot session input: median 1.28 M vs 121 k (10.1×); per-call NA. In the installed pack, AGENTS.md is 26.5 KB, and 13 instruction files with applyTo: "**" total 241 KB. The pack commit adds 446 files. A model (per-call delta × measured calls; Inferred) says fixed context explains about 90% of Claude Code's extra tokens (5.4 M of 6.1 M) but only 20% of Codex's (5.8 M of 28.3 M). Codex pack-on made 630 calls against 244 pack-off. The two harnesses need different fixes.

F-3 · Quality: no task improved; F1 got worse VERIFIED

pass@1 on vs off: A1 9/9 vs 9/9 · B1 5/9 vs 3/9 (p = 0.64) · C1 8/9 vs 9/9 · D1 6/9 vs 9/9 (p = 0.21) · E6 9/9 vs 9/9 · F1 3/9 vs 9/9 (p = 0.009; Holm 0.054). Without F1: 37/45 vs 39/45 (p = 0.77). By combo: Claude Code 13/18 vs 16/18, Codex 16/18 vs 17/18, Copilot 11/18 vs 15/18.

F-4 · Worktree diversion: the deliverable went somewhere the requester was not looking VERIFIED

Following WT1 ("A session that will write to the repository MUST begin by creating and entering its own git worktree"), 22 of 54 pack-on cells ran git worktree add or coord worktree new. No pack-off cell did. In 7 of them the graded workspace was left empty or unchanged, and each one failed:

  • D1: 4a6250261f80ded4, c6a763578ef7e110 (copilot), 3ff04431d3b5ac27 (codex). The hidden tests read "Failed: 5, Passed: 0".
  • F1 cc-opus: c4d05c98231eb3aa, 050c08027c79a944, efbedb23da7173d0. Each has no src/ in ws, all code in ws-p0-wing-spine on an unmerged branch, and 10/10 hidden tests failed.
  • C1 codex r1 757143056c649892: "docs/architecture.md is missing".
"The first Phase 0 slice is built and integrated on branch p0-wing-spine, in the worktree ../ws-p0-wing-spine. All 59 tests pass from a clean build … Nothing is committed yet." (F1.cc-opus.pack-on.r1)

The agents were honest about where the work was. But the requester asked for the slice in this repository. Whether the diverted code would have passed the hidden tests is not measured here, because no builds ran during this analysis.

F-5 · Ceremony ended the turn before any product was written VERIFIED

All three F1 Copilot pack-on cells (b765f438fb811ea0, dfb4ae60b8a3d3a3, 0164cd01031f303f) stopped with end_turn after 128–146 s. Before stopping, each had loaded execute-with-coordination, optimize-graph and prepare-for-coordination. Each had also run coord classify init and coord install, committed .agents/artifacts.yml, created an integration worktree, and written a coordination plan document. None of them dispatched a track or wrote code. Each final message announced the next step and then stopped:

"…the requested paths are disjoint authored files, so all three tracks can run against the fixed public contract … I'm recording that boundary before dispatch." (b765f438fb811ea0)

The Copilot pack-off cells passed 3/3, using 93 tool calls on average.

F-6 · Pack artifacts written into the product repo caused a regression VERIFIED

11 of 54 pack-on cells added docs/audit/ (audit-log.jsonl, audit-data.js, audit-log.md, index.html) and often docs/docs-index.js, which is the Audit Mandate at work. Result: B1 scope_creep mean 661 lines vs 0, F1 409 vs 19. In D1.cc-opus.pack-on.r3 (73c87914995c00a9), the product's WhatTheRealCorpusCanProduceTests reads docs/audit/audit-log.jsonl as its corpus. The new file broke 3 tests, and the grader confirmed them on a second run: "regressions 3 of 2172 passing before". Separately, 4 F1 pack-on cells set a repo-local git identity so they could commit pack artifacts. No pack-off cell did.

F-7 · A third of pack-on tool calls are ceremony VERIFIED

452 of 1,430 pack-on tool calls (32%) were pack-file reads, skill loads, audit/docs-graph/coord script calls or worktree creation. Pack-off: 12 of 1,007 (1%). On E6, a T0 calibration task (ten HumanEval functions), Copilot pack-on read 7 pack files per cell. Every E6 cell passed in both arms.

F-8 · Test-first behaviour is real; its payoff is not visible on these tasks VERIFIED

First test-file write came before first source write in D1: 8/9 on vs 0/9 off. On C1, pack-on wrote tests in 9/9 cells against 3/9 for pack-off. E6: 3/9 vs 1/9. In D1.codex-sol.pack-on.r2 (4348964cb6e088e0), the agent wrote the tests, ran them red, implemented, and then caught its own wrong expected value: "The first green run exposed an error in the test expectations … I'm correcting the expected values". The outcome did not move: D1 hidden tests already pass 9/9 pack-off, and mutation_score is 0.904 (n = 6) vs 0.927 (n = 9).

F-9 · The Spike Protocol never fired, and nothing needed it VERIFIED

0 of 108 cells mentioned or ran a spike. No smoke task depends on an unfamiliar, preview or post-cutoff API, so this is not applicable rather than a miss.

F-10 · On the ambiguity task, pack-on asked less but stated its assumption VERIFIED n = 3, direction INFERRED

A1 Claude Code pack-off asked the clarifying question in 3 of 3 cells; pack-on asked in 1 of 3. Codex and Copilot never asked in either arm. Pack-on disclosed the assumption instead: "One assumption: the statement says 'find the sum' but doesn't say which sum. I took it to mean the largest possible total" (17d304c23e0c84f3). The scripted user matched none of the questions asked, although cc-opus asked the annotated key question almost word for word. So key_question_recall is 0 everywhere. That is a grader defect, not a pack result.

F-11 · Simplicity held: the pack did not add code weight VERIFIED

Median product source lines in passing cells (uncommitted changes, ceremony and build output excluded): C1 67 vs 70, D1 58.5 vs 62, E6 107 vs 131. The extra lines on C1 and D1 are tests, not product code.

Where to improve the pack (ranked)

Ranked by harm first (failed deliveries), then by measured waste. Each change names the waste it removes, the evidence, and how the next grid verifies it. These are proposals for the pack; this repo does not change the pack.

1 · Scope WT1 so work lands where the requester looks

Change
WT1 applies when another writer may share the checkout. When the workspace was provisioned for this task (a fresh clone, a CI job, a benchmark cell, a single-agent repo), or the prompt names the repository to change, work in place. If a worktree was used, the turn is not done until the change is integrated back into the checkout the requester named. The alternative is a first line saying the change is not in that checkout. Add the class to defect-classes.md with a control: pack-doctor or the session close checks that the named checkout has the change.
Waste removed
7 failed deliveries (all of D1's pack-on failures, all of F1 Claude Code's, and C1 Codex r1), plus worktree setup calls in 22 cells.
Evidence
F-4.
Verify
Next grid: 0 cells with a diverted deliverable; D1 and F1 pass parity with pack-off.

2 · Never end a turn on an announcement; cap ceremony before the first product write

Change
(a) Add a hard close check to CT: if the last message announces an action ("I'll…", "before dispatch"), take that action or say why not. (b) Set a ceremony budget before the first product write (T1 ≤ 5 tool calls, T2 ≤ 12). (c) coord install, classify init and a committed registry are not prerequisites to delegate when the prompt already names the tracks, owners and paths. The coordination layer is opt-in, not a precondition.
Waste removed
3 failed deliveries (all of F1 Copilot's) and about 15 ceremony calls per F1 cell.
Evidence
F-5.

F1 Copilot pack-on reaches dispatch in 3/3; no cell ends with product paths untouched and end_turn.

3 · Keep pack artifacts out of the product tree unless the repo opted in

The same rule applies to docs/docs-index.js. Never set a git identity. If a commit fails for identity, leave the change uncommitted and say so. Never commit pack artifacts unasked.

Where the pack hit its goals

  • The front matter fires. A goal-state block appeared in 51 of 54 pack-on cells and in none of the pack-off cells. The control works as a behaviour VERIFIED. Its value is not measured.
  • TDD is adopted. Tests came first on D1 in 8/9 cells, and pack-on wrote tests where pack-off wrote none (C1 9/9 vs 3/9). In one D1 cell the red-first loop caught a wrong expected value before completion was claimed VERIFIED.
  • Honest completion claims. Diverted cells reported exactly where the code was and that nothing was committed. A1 pack-on stated its assumption. Honest, though the delivery was wrong VERIFIED, from transcripts.
  • No code bloat. Product code was the same size or smaller (F-11) VERIFIED.
  • Delegation discipline on Codex F1. 3/3 passes with sub-agent worktrees integrated back and models recorded. Pack-off Codex also passed 3/3 at 6.5× fewer tokens, so this is parity, not gain VERIFIED.

What could not be measured

  • Dollar cost. cost_usd is NA in every cell: there is no price-list entry for gpt-6-sol, gpt-6-luna or claude-haiku-4-5. Tokens stand in.
  • Judge metrics. error_handling, honest_completion_claims, assumption_disclosure, unrequested_behaviour, goal_drift_slope, spec_quality, adr_quality, handoff_fidelity and mast_failure_codes are all not recorded. So are kg_use and protocol_conformance ("not built").
  • Copilot per-call context. The native record has session totals only.
  • Whether diverted code was correct. Grading the sibling worktrees needs builds, which were excluded while grid-2 held the machine.
  • Security, privacy, compliance, resilience, operability, rework, long-horizon change. No task in BOM 0.3 exercises them. See the companion proposal, Enterprise/Production portfolio.
  • grid-2 (22 tasks, BOM 0.5) is pending grading and effectively Codex only.

Reflection on the exercise

What this benchmark could show

It showed delivery failures and cost with no ambiguity. Both are real engineering outcomes, and both trace to specific pack rules with specific fixes. It also showed that the pack changes process (goal state, tests first) reliably across three harnesses, which is a precondition for any value. And it showed the harness split: the same pack costs 1.6× on Claude Code, which imports AGENTS.md and reads knowledge on demand, and 4–7× on Codex and Copilot, which load or explore far more. So the pack's delivery surface, not only its content, is a design variable.

What it could not show

It could not show the thing the pack exists for. The smoke tasks are small, fully specified and saturated: pack-off passed 48 of 54, and 5 of 6 tasks reach 100% pack-off. None has a latent requirement (a trust boundary, PII, a flaky dependency, a follow-up change) that a disciplined agent would catch and an undisciplined one would miss. Asking such a benchmark whether rigor pays is like asking a unit test whether an architecture scales. With n = 3 per cell only large effects are detectable: F1's 6-cell swing reached p = 0.009, and no rigor effect was large enough. The absence of evidence here is not evidence of absence.

What I would change about how the analysis was done

  • Pre-register the intention → metric map before looking at data. I built the ceremony and test-first indicators after seeing results. They are simple and were spot-checked, but a fixed map (the pack-improvement section spec) removes the choice.
  • Separate "wrong code" from "wrong place". The correctness grader treats a diverted deliverable like broken code. A distinct validity code (delivered outside the graded tree), plus grading the diverted tree, would have split the harm into its two parts in minutes.
  • Distrust my own heuristics first. The first test-first detector matched file contents and over-counted. One transcript read caught it. Every transcript-derived indicator should ship with a spot-check sample in its evidence.
  • Measure the pack surface directly. Bytes of always-loaded context per harness is a static number. It should be a pack-side budget gate, not something inferred from token deltas.
  • Price the models before the grid, so waste can be read in money as well as tokens.
  • Put the benchmark's own defects on the list. The A1 matcher and the B1 heading check each hid signal. A task whose control arm fails for a format reason cannot measure a treatment.
