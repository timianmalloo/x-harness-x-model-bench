The prompt

You are running ONE lean benchmark for ONE harness/model combo on this repository's bench. Work alone: no
sub-agents, no coordination layer, no worktree other than the one you create. Use `python`, never `python3`
(Windows). Tokens are the only cost unit; never write USD.

SETTINGS (the operator fills these in; do not change them):
  COMBO_ID    = <short id, e.g. codex-sol>
  HARNESS     = <claude-code | codex | copilot | grok | agy>
  MODEL       = <pinned model id, e.g. gpt-6.1-sol>
  EFFORT      = <high>
  CONTEXT     = <token count, or default>
  TASKS       = [S1, S2, RS1, RS2, RW1, RW2, NG1, NG2, SM1, SM2]
  ARMS        = off, on            (off = no pack; on = the AI-Forward pack)
  PACK        = C:/Projects/ai-forward@ed9625a78690aeba04d0b6693ad296ba5e6a0cd9
  REPETITIONS = 2
  PARALLELISM = 3                  (grok and agy are capped at 1 cell at a time regardless)

GOAL: a completed, verified bench run of COMBO_ID in its own worktree, an HTML run summary open in Chrome, and one
HANDOFF line the grading prompt can use. DONE WHEN: `bench verify` passes on the run, the summary is open, and the
HANDOFF line is printed. NOT IN SCOPE: judging with model calls, comparison reports, pack analysis (Prompt 2 does
those), editing bench code, pushing anything.

STEP 0 - start state (stop and report if any check fails)
  - In C:\Projects\x-harness-x-model-bench: `git pull --ff-only origin main` succeeds (local changes that block it
    are a stop; never stash or reset them). Record `git rev-parse HEAD` as BASE.
  - RUN_ID = lean-<COMBO_ID>-<UTC yyyymmddThhmm>. Use it for the branch, the worktree and the run.
  - CELLS = C:\Projects\bench-cells\<RUN_ID>: this run's own cell folders, so runs of other combos on this host
    never share one. Every `uv run bench` command from STEP 5 on carries `--cells-root <CELLS>` BEFORE the
    subcommand, e.g. `uv run bench --cells-root <CELLS> run <RUN_ID>`.

STEP 1 - the worktree
  - `python docs/ai-forward-pack/scripts/coord-core.py worktree new --branch bench/<RUN_ID> --session <RUN_ID>`
  - Read its path from `git worktree list` (call it WT). Do every later step inside WT, with absolute paths.
    Never write the main checkout after this step.

STEP 2 - the pinned builds (inside WT)
  - `uv run bench tools install --vendored C:\Users\malla\.harness-bench\agy-1.3.3\agy.exe`
  - `uv run bench tools install`
  - The output lists one line per harness with its version and sha. Check HARNESS's line is present.

STEP 3 - the environment for the cells
  - Always: unset XAI_API_KEY.
  - grok: HB_GROK_CRED_HOME=C:\Users\malla\.harness-bench\grok-cred (the bench Grok login; never ~/.grok).
  - claude-code: HB_CLAUDE_OAUTH_TOKEN = the contents of C:\Users\malla\.harness-bench\claude-oauth-token.txt.txt,
    whitespace stripped. Never print the token; pass it only in the environment of the bench commands.
  - copilot: nothing (the profile sets COPILOT_AUTO_UPDATE=false and runs copilot -p behind the local adapter).
  - agy: nothing (the profile disables its auto-update and seeds its permissions).

STEP 4 - the matrix (inside WT; write it to WT\runs\<RUN_ID>.matrix.yaml, which git ignores)
  schema: bench-matrix/3
  ring: {tag: lean}
  bom: {file: bench/bom.yaml, subset: [<TASKS>]}
  repetitions: <REPETITIONS>
  harness_parallelism: {grok: 1, agy: 1}
  arms:
    - {id: "off"}
    - {id: "on"}
  comparisons: [["off", "on"]]
  combos:
    - {id: <COMBO_ID>, harness: <HARNESS>, model: "<MODEL>", effort: <EFFORT>, context: <CONTEXT>}

STEP 5 - plan, then confirm (inside WT, with the STEP 3 environment)
  - `uv run bench plan --matrix runs/<RUN_ID>.matrix.yaml --run-id <RUN_ID> --parallelism <PARALLELISM>
    --arm on=<PACK>` and read the table: every cell has HARNESS's pinned build, the pack-on arm shows the pack
    revision, the pack-off arm shows "no pack", and the cell count is 10 x 2 x REPETITIONS. A refusal (HB-PRE-*) is a
    stop: report it verbatim.
  - Then the same command with `--confirm`.

STEP 6 - run (inside WT)
  - `uv run bench run <RUN_ID>`, as a background job. It launches the cells and runs a deterministic grading pass at
    its end. Watch it with `uv run bench status <RUN_ID>` every 10 minutes; report each check in one line
    (cells ended / running / validity counts).
  - Early check: when the first 2 cells have ended, look at `bench status`: a cell with validity code HB-VAL-002
    (model mismatch) or HB-VAL-010 (served effort or context differs from the pin) means the harness did not serve
    the pinned model or setting. HB-VAL-011 (setting not recorded) is a warning, expected for agy's context. Stop the run (`uv run bench stop <RUN_ID>`) and report which.
  - Stop rules: the engine reports it is down twice; the host becomes unstable (record the evidence first); an
    authentication failure pauses launches (HB-CELL-202) and the decision times out. Never edit a log or a run file.

STEP 7 - verify (inside WT)
  - `uv run bench verify <RUN_ID>` must exit 0. Exit 5 is an integrity failure: report it, do not repair it.

STEP 8 - the run summary (inside WT)
  - `uv run bench report <RUN_ID>` (writes runs/<RUN_ID>/report.html).
  - Write runs/<RUN_ID>/run-summary.md from `uv run bench status <RUN_ID> --json` and the report: the settings
    block; BASE and WT; the plan's builds; cells by outcome and by validity (codes named); the served settings read
    back per arm (model, effort, context) with their source; tokens per cell by arm (mean, min, max; fresh input,
    cache read, cache write, output, reasoning); wall minutes per cell by arm; every warning code with its count; the
    run's start and end time and its total wall time. Every number comes from the bench's output; label anything you
    computed (a mean) as computed.
  - `python docs/ai-forward-pack/scripts/render-markdown.py runs/<RUN_ID>/run-summary.md --open` (HTML beside it,
    opened in Chrome). If it prints "not opened: <why>", say why.

STEP 9 - the hand-off
  - Write runs/<RUN_ID>/handoff.json: {"run_id", "worktree": WT, "branch": "bench/<RUN_ID>", "base": BASE,
    "cells_root": CELLS, "combo": COMBO_ID, "harness", "model", "effort", "context", "pack": PACK, "cells", "verify": "ok",
    "summary": "<path to run-summary.html>"}.
  - Print, as the last line of your reply:  HANDOFF: <RUN_ID>@<WT>
  - Leave the worktree in place (Prompt 2 reads the run from it). Do not commit the run (runs/ is git-ignored) and
    do not push.

Report at the end: one table (step, result, evidence), the HANDOFF line, and anything that did not go as written.
