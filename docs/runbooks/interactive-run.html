Runbook: the interactive run

The prompt page is docs/benchmarkpromps/interactive-benchmark-prompt.html. The headless run (lean-benchmark-run-prompt.html, runbook-lean-comparison-run) stays as the automated alternative.

1. Why this mode

The operator's concern (2026-10-14): a headless cell (claude -p, codex exec, copilot -p behind the adapter) is one fresh process per task. A developer instead works in one interactive session that runs for hours. Sub-agents in one session were rejected, because the pack is loaded once, at CLI startup, from the folder. A sub-agent inherits its parent's setup, so one session cannot hold both arms. The operator chose (2026-10-14): one paste per arm, one repetition, and the headless prompt kept as the alternative.

The operator's changes (2026-10-15): prepare takes every lean task (the lean ring's list) and the latest pack (HEAD of ../ai-forward) by default, and several CLIs in one call (--harness claude, codex, copilot). Each session grades itself and ends with its report open in Chrome. The analysis prompt only gathers the graded runs and compares them.

2. How it works

StepWhat happensCode
prepareOne run per CLI named in --harness (commas, spaces or both; claude = claude-code), all with one time stamp. Tasks default to the lean ring's list (bench/rings/lean.yaml), the pack to HEAD of ../ai-forward. <out>/<run>/off/ and .../on/: each is one git repository with tasks/<ID>/ (the base tree from workspace.task_source, never the hidden tests) and .bench/ (next.py, queue.json, grade.json). on gets the pack through workspace.install_pack. off is checked to hold no instruction file. Both arms get the bench's line-ending rule (* text=auto eol=lf) in .git/info/attributes, which outranks the pack's .gitattributes. Prepare then refuses (HB-PRE-013) arms whose tasks/ files differ in line endings (ARM-FAIR-A). Task trees hold only the files the source commit tracks. Each arm gets .venv (git-excluded), made from the python the operator's shell resolves to (session_python; HB-PRE-014 when there is none). HEAD after prepare is the arm's base. Each arm also gets .bench/launch.ps1 and .bench/launch.sh (cd, the venv, PIP_REQUIRE_VIRTUALENV=1, the pinned CLI line from interactive.LAUNCH, and .bench/paste.txt as the session's first message) so the window needs no typing (BOOT-STEPS-A).interactive.prepare, harnesses, default_tasks, latest_pack, write_launch_scripts

runbench interactive run --harness a,b,c: the whole comparison in one command. Per harness in turn: prepare, launch both windows, wait for both arms' summary.json (polled every POLL_SECONDS), then the next harness (one CLI at a time); at the end gather, compare, and open the comparison.interactive.run_all, wait_graded
sessionThe CLI starts with interactive.PASTE as its first message (the page shows it verbatim; a test keeps the two equal; the launch scripts read it from .bench/paste.txt). next.py hands out one task at a time and stamps start and end times. Closing an item first copies its task folder to .bench/snapshots/<ID>/turn-<n>/: the task as handed off, which collect grades. Closing an item also commits that task's folder, and only that folder, with hooks off. A later task's git stash or reset therefore cannot take the work. The sha, or why there is none, goes to state.json, and a failed commit becomes a report warning (TASK-ISO-A). It prints UTF-8 and records the interpreter that ran it; collect warns when that was not the arm's .venv. A record belongs to the arm it states it was launched in, and a task boundary is a next.py call whose time window holds a hand-out in state.json (REC-ATTR-A).interactive_next.py
session: gradingThe next.py call that closes the last item starts grade.json's command, bench interactive collect <run> --arm <arm> --open, detached (a new hidden console and process group, out of the CLI's job where allowed), with its output in <run>/grade-<arm>.log. It prints nothing, so the session is not told it is graded; state.json records the start or why it did not start. A later call does not start it again.interactive_next._grade
collect: gradeEach task is graded as handed off (TASK-ISO-A). Its overlay is next.py's copy from the hand-off, every file of it. Base files the copy lacks are reported as deletions the replay cannot make. Files the final tree changed after the hand-off, a later task's edits, are not graded and are reported as a warning. With no copy, the overlay is the task's changes against the base in the final tree (committed or not, plus new files). That is the item still open at the end, or an arm prepared before 2026-10-16. When such an item was closed, collect warns. A two-turn task gets turn-1/ and turn-2/, each from its own copy. A replay run applies the overlays through the real engine, the synthetic agent and the in-run grading pass, which is the path bench discriminate uses. Scores come from readiness.run_scores: correctness, the property check and the change-set drift scores (scope_creep, drift_task_implied_lines, drift_machine_lines). Files changed outside tasks/ and .bench/ are listed.interactive.build_overlays, replay, outside_task_folders
collect: sessionThe session's records are found under the CLI's home by the arm path (find_records) or given with --record. Each is read by the harness's reader; agy's conversation db is read by agy.read_db. Model and tool calls are split per task at the next.py calls (split).interactive.read_session, session_metrics
collect --openThe arm's own report, <run>/collect/<arm>/report.md, rendered to HTML and opened in Chrome. A failed grading opens <run>/grade-<arm>-failed.md instead.cli.cmd_interactive, interactive.report(only=arm)
gatherAfter every CLI has exited: re-read the session records each graded arm's grading found (the search runs again only for an arm whose grading found none, because a new search also matches any later session that named the arm folder, as this session's own transcript did in the 2026-10-15 smoke) and write each run's two-arm interactive-report.md. An arm not graded is listed, not graded.interactive.gather, refresh_session
reportThe collected arms side by side: scores, drift (with the largest discretionary files behind each scope_creep count, DRIFT-EVIDENCE-A), minutes, session tokens one bucket per row with an on ÷ off ratio (TOK-BUCKET-A), per-task tokens one column per bucket, served settings, tool failures and the non-zero exits among them, pack hook events, hook seconds, pack hook seconds, model and tool seconds, warnings. A Stale scores line names any arm graded by another bench commit, a dirty tree or an older task version, with the collect to re-run (STALE-GRADE-A; collect records graded_with).interactive.report, stale_grades, drift_files
comparebench interactive compare: every harness across all its runs, the sessions being the repetitions. Per task: n, passes per arm, sessions where the arms disagreed, median tokens per bucket and minutes per arm. The heading says how many more sessions a per-task verdict needs (SESSIONS_FOR_VERDICT = 3). Written to <out>/interactive-compare.md.interactive.compare

The end-to-end test (tests/test_interactive.py) plays the fixture two-turn task's reference solution in one arm and its naive solution in the other, through the real path. It requires the scores the fixture declares (property_check_pass 1 and 0; rework_ratio 0.2500 and 1.0000), the same values bench discriminate reproduces.

Hook time and failure kinds (2026-10-17):

  • Hook seconds. The report gives the time inside every hook the record times. That covers pack and user-level

hooks together, so the pack's share is on minus off. Only Copilot times every hook, with hook.start and hook.end pairs. In run int-copilot-20261015T1529 that was 182.2 s over 250 hooks (on) and 1.1 s over 4 hooks (off). Claude Code keeps no start for a hook, and Codex records none, so both read not recorded, never 0.

  • Pack hook seconds. From pack revision 110, the pack's dispatcher times itself. prepare creates

.git/ai-forward/hook-times.jsonl in both arms, and each dispatch appends one line: host, event, hooks, start, ms and exit. The report sums them for every harness, Claude Code included. The time runs from the dispatcher's main() to its exit, so the host's git -> sh -> python launch is outside it, and Copilot's own hook seconds are the larger figure. A pack-off arm reads 0 dispatches. An arm prepared with an older pack reads not recorded.

  • Model and tool seconds. These use the per-cell views' rule: the union of the call spans across all of a

session's records. A model call with no start makes model time not recorded, never a partial sum.

  • `tool_failures_exit`. These are the tool_failures that were a command that ran and exited non-zero: a

grep with no match, or a test run expected to fail. In the 2026-10-15 runs they were 26 of 27 failures (Codex on) and 18 of 22 (Copilot on). So tool_failures alone is not agent error.

4. Limits

  • One run is one session per arm: a paired observation per task, never a significance claim. Sessions are the

repetitions: run the same CLI again (bench interactive run --harness <cli> on another day, arm order alternated by starting the on window first), and bench interactive compare pairs every session per task. A per-task verdict needs at least 3 sessions per arm; below that the comparison says so in its heading.

  • Context carries from task to task in a fixed queue order, the same in both arms. This mode is not comparable with

the headless runs.

  • The pack's per-message rules fire once for the whole paste (one user message), not once per task.
  • An overlay cannot replay a deleted file. Collect lists deletions as a warning, and the deleted file stays in the

graded tree.

  • The catalog's process metrics (catalog 0.9) and attention_drift need a record per cell and are not graded in this

mode. Collect reports tool calls and failed tool calls per task from the session record instead.

  • The session's own grading reads its record while the session is still open, so the last turns are missing. Copilot

writes usage as a session summary at exit, so its local report has no tokens and its per-task tokens are not recorded. gather re-reads every record after the CLIs exit; the comparison uses those numbers.

  • The detached grading survives the tool call. Whether it survives the CLI's exit depends on the CLI's job object

(not measured per CLI), so the operator exits only after the report has opened. If none opens, the log names the failure and collect --open reruns it.

  • The installed CLI builds are newer than the bench's pinned builds. The context windows measured for the pins

(Codex 872000, Copilot long_context) are read back from each record where it carries them: Codex's context tokens, Copilot's tier. Claude Code and agy record no window.

  • Copilot starts on its default model (gpt-5.5), so the operator picks gpt-6.1-sol in

each window's model picker before pasting (the operator, 2026-10-16; both 2026-10-15 records show the startup model gpt-5.5, then a model_picker switch). The report warns when the arms were served different models (served_model_warnings).

  • The paste approves every tool call (each CLI's own flag, the same in both arms), because one paste runs

unattended.
