What each coding harness costs in tokens and time

Claude Code, Codex and Copilot ran the same 10 coding tasks on one Windows machine. This page compares only what each harness spent: tokens, clock time, model requests and tool calls, and how far its edits strayed from the task.

1 What was benchmarked

Each cell is one harness given one task in a fresh copy of a real open-source Python repository, with a fixed prompt and a 45-minute budget. The harness works on its own until it stops. A grader then runs the task's hidden tests and checks, and the bench records every model request, tool call and file change.

  • 10 tasks on 10 repositories, in five pairs: security (S1 microdot, S2 bottle), resilience (RS1 prometheus client, RS2 structlog), rework (RW1 humanfriendly, RW2 schedule), working from a vendored API without guessing (NG1 cachetools, NG2 tomli), and simplicity (SM1 tinydb, SM2 jmespath).
  • Two repository conditions. Bare: the repository as published. With instructions: the same repository carrying an agent-instruction kit (an AGENTS.md, a CLAUDE.md, 13 instruction files marked to apply everywhere, a skill library and tool hooks). This page does not judge whether the kit helps. It only shows what each harness spends in each condition.
  • Each task ran twice per harness and condition, in two batches: 10 tasks × 2 conditions × 2 runs = 40 cells per harness. Up to three cells ran at once.
  • What is measured per cell: tokens by type (fresh input, cache read, cache write, output), the harness process's wall-clock time, time inside tools, model requests, tool calls by kind, the change set against the task's allowed files, and the hidden test results.

All measures

"Discretionary drift" counts lines changed outside the task's allowed files. It leaves out tool caches (.pytest_cache, .mypy_cache), files written by hooks and the audit script (.agents/log, docs/audit), and test files that every harness wrote for that task (the task's allowed-file list omits a test file the task needs). "Task orientation" is the in-scope share of all changed lines. Both use the bench's own drift grader, run again on the archived working copies.

4 Observations

  1. In a bare repository Codex is the cheapest and fastest, and Copilot is close behind. Codex used 204k tokens and 1.8 min per cell, Copilot 235k (+15%) and 2.1 min, Claude Code 469k (2.3× Codex) and 2.2 min. Claude Code sends a larger fixed prompt (first request 21.0k tokens vs Codex 11.8k), and each later request carries more context (29k vs 18.5k on average), over more requests (13.7 vs 9.8).
  2. With instruction files in the repository, the harnesses separate sharply. Copilot rose to 2.25M tokens and 6.4 min per cell: 4.8× Codex (465k, 2.3 min) and 2.9× Claude Code (762k, 2.3 min). Section 5 traces the cause to how Copilot builds its prompt and runs hooks.
  3. Most tokens are cache reads. Cached prompt text is 83–89% of Codex's tokens and 87–94% of Claude Code's and Copilot's. Output is small everywhere: 3–10k tokens per cell. Cost is driven by how much context is resent on each request and how many requests are made, not by how much the model writes.
  4. Copilot makes the most unrequested edits; Codex the fewest. Copilot edited files outside the task in 16 of 20 cells in both conditions: READMEs, docs pages, pyproject.toml, type stubs. Codex did so in 0 of 20 bare cells (1 with instructions), Claude Code in 3 and 2. The volumes are small (Copilot about 21–26 lines per cell).
  5. The outcomes were the same. Every cell passed its task's functional tests (pass@1 = 100% for all six series). Hidden property checks passed in 75–80% of cells for every harness. Here, spending more tokens or time did not buy a better result.
  6. The harnesses work in different styles. Codex does everything through one shell tool (8.6 calls per bare cell), often batching several commands into one call. Copilot reads in small steps (10 view calls per cell, 25 tool calls in all). Claude Code sits between them (18 calls: edit, shell, read).

5 Why Copilot and Codex differ on the same model

Both ran gpt-6.1-sol. The differences come from the harness: what it puts in the prompt, how many requests it makes, how it uses tools, and its default settings. Each harness keeps its own session record in the archived cell, so this can be read directly rather than inferred.

harness's own instructionstool or skill catalogueAGENTS.md / CLAUDE.mdinstruction files inlined

Measured from one cell per condition (identical across cells of a condition, up to the repository's own files). Codex's tool definitions are not in its record, so its bars leave them out. Characters, not tokens: roughly 3–4 characters per token for this text.

Bare repository: nearly the same per request, more requests and tool calls for Copilot. Input per request is 19.0k tokens for Copilot vs 18.5k for Codex. Copilot makes more requests (median 12 vs 7.5) and 3–4× the tool calls (24 vs 6.5 in the session records). It also runs at reasoning effort medium vs Codex's low: 1,390 vs about 110 reasoning tokens per cell. Net result: +15% tokens, +15% time.

With instructions: Copilot resends the whole kit on every request. Copilot's system prompt grows from 19k to 329k characters. It inlines all 13 instruction files marked applyTo: "**" (235k characters), both AGENTS.md and CLAUDE.md (55k), and a larger tool and skill catalogue (19k). Codex adds only AGENTS.md (27k) and a skill list (20k), and reads other documents only if it chooses to (it did not). Input per request: 107k vs 37k tokens. Copilot also makes more requests (19 vs 10), so total input is 2.02M vs 0.37M per cell (medians).

Hooks account for most of Copilot's extra time. The kit's hooks ran 60 times per Copilot cell (22 before a tool, 39 after it, plus session and prompt hooks), a median of 173 s per cell from the hook start and end events. That is most of the rise in wall clock from 2.1 to 6.4 min.

How much deeper this can go

  • Available now, not yet used: every tool call with its arguments and timing (Copilot events, Codex rollouts), Codex's per-request token curve (in one cell with instructions it grows from 21k to 47k over 9 requests), and the full text of every prompt. These can show where requests are spent: exploration vs editing vs verification.
  • Not recorded: Copilot's per-request token sizes (only per-session totals; the 107k above is an average), model time for Claude Code and Codex, and Codex's tool-definition size.
  • Controlled reruns would separate the causes: Codex and Copilot at the same reasoning effort, the kit with instruction files narrowed from ** to the paths they govern, and the kit with hooks off. Each is a small run (a few tasks, about 20 cells) on the existing bench.
