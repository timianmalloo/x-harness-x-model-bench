**Checked and held (the brief's list).**
- *Driver open / send / close.* The channel survives between turns because `_end_process` (stdin close) stays in the outer `finally`; `run_turn` stays a wrapper. Usage across turns is per call (spike E4: "independently keyed per call"), so the sum is additive; `native_record` profiles read one session record. Verified in the spike note.
- *`_attempt` lifecycle.* One worker runs the whole cell in sequence (`_cell_worker`, `_run_cell`; outcome and archive follow `_attempt`), so a snapshot never overlaps the final archive. A `Cause.archive` set on `result.cause` is reached by `_classify` after the kill and memory causes, which is the right order.
- *Budget clock and spend.* `_after_append` runs on the engine thread; gating on `turn == 1` keeps one clock, and the copy counts against it (D-J7). Today `_after_append` resets `prompt_mono` on every `cell.prompt_sent` (`engine.py:277-283`) and `_run_cell` reads only `result.usage` (`engine.py:662-663`): both are real bugs and the fixes fit.
- *Snapshot order.* Rename, then rows, then the event, then `prompt_sent{n+1}`: each append is acked only after `_append_now` (`future.set_result` follows), so the order the model checks is the order the code writes. Rows are not in the model; T-SNAP-3 carries them (finding 1).
- *Crash classification and resume.* `ClassOf` is conservative in each window (a lost `turn_ended`, a persisted but unsent `prompt_sent{2}` and a finished-but-unrecorded cell are all `crashfail`); only a clean between-turns cell is `crashbetween`. `SnapAllowed` requires the adapter gone, matching reconcile's kill-then-confirm order. `Crash` clears `tmp` and keeps `fin`; the redo path (`fin` complete, no event) completes by `SnapRecord`, as the recovery rule says.
- *Outside the model, accepted:* the process-count gauge and a lingering writer (ADR-0015 section 4); the Job Object kill-on-close that makes "the adapter died with the engine" true (F3; not modelled; Inferred from `procs`); the 3.6e8-state fingerprint margin of 2.8e-3 at US-44 bounds (stated by the design, carried by the smaller runs).

**Seam disagreements.** (1) W1-J vs W1-B on one recovery rule: HB-LED-008 vs HB-LED-005, and who builds it in E2 (finding 1). (2) W1-J s2 and W0 s4 line 248 vs W0 rev 6's folder form: stale `stale_temps(target)` and a non-recursive "archive root" (finding 2; W0 rev 6 finding 1). (3) W1-B still documents the withdrawn `sweep_temps(target, ...)` and the `is_held` guard; its author re-reads rev 6 (outside this lens's edit rights).
