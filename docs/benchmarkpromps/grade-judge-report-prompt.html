Prompt 2: analyse the lean runs

Paste into one CLI session in C:\Projects\x-harness-x-model-bench (full permissions). Nothing to fill in: it finds every finished lean run of today's campaign itself, checks it, and writes four pages: run health and issues, behaviour (drift, ceremony, over-thinking), cost, and pack-on vs pack-off. Model judges are off unless you switch them on.

How to use it

  1. Paste it whenever you like. Runs still going are listed as pending and left out; paste again later to add them. To limit it to some runs, paste their HANDOFF: lines under RUNS.
  2. Only runs started at or after SINCE (Prompt 1's SESSIONS_SINCE) are analysed. The 2026-10-13 runs are an earlier campaign under another catalog, profile set and pack revision: they are listed, never pooled or compared as if like for like.
  3. To also grade with the model judges, change JUDGE = no to JUDGE = yes. Judging costs tokens and needs BENCH_OPERATOR_EMAIL.
  4. It ends with the four pages open in Chrome and committed locally (not pushed).

    recorded".
  - A run with fewer than 2 repetitions per cell has no spread; say so rather than draw a conclusion from one cell.
  - Never compare today's runs with the 2026-10-13 runs as if like for like. Those were graded under catalog 0.8 (the
