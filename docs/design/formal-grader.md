## Responsibility

One responsibility: **turn one archived G-cell (G1 or G2) into the six `formal`-grader score rows.** It is a pure function of the archive, the frozen task version (its `formal:` block and `oracle/` assets) and the catalog version — the same contract every other grader in `docs/design/phase3-graders.md` already honors. It is not responsible for: running the reference model or reference proofs at task-authoring time (that is `/new-bench-task`'s job, producing the `oracle/` assets this grader reads); judging a bug narrative that is not the seeded bug (deferred, DR-FM2); the `bench validate` scenario-7 rule itself (`config.validate_task`, already partly built — G16 below).

## Data model (settled first)

**Bounded context:** grading (unchanged from row 16 — `docs/design/phase3-graders.md`'s "Data model" section). Ubiquitous language adds: *given statement* (the frozen properties/theorem-signatures/fold-definition file(s) the agent must not alter), *statement hash* (the one content hash over the given-statement bytes for a task version), *recorded trace* (a fixed sequence of real-fold lease events, an oracle asset), *bug-seeded variant* (a task-authored, buggy copy of the fold or a bug-perturbed trace set, an oracle asset), *reported bug* (a free-text claim in `BUGS.md`, G1 only), *confirmed bug* (a reported bug whose named test fails on the real code and passes on the reference fix).

**Aggregates.** This design adds none; it writes into the row-16 aggregate exactly as every other grader does.

| Aggregate (root) | The one invariant it protects | How this design honors it |
| --- | --- | --- |
| Grading pass (`grading_id`) | GradedOncePerPass (row 16) | `formal.grade_cell` returns exactly one `Score` per key in `inp.metrics` (its applicable set), same as every grader; no new fact, no new writer. |

**Grain.** `scores` is unchanged: one row is exactly one metric value for one cell in one grading pass, key `(run_id, grading_id, cell_id, metric_id)`. This design adds six metric ids to the set the dispatch (row 16, `runner.applicable`) already routes by `grader: formal` — no schema change.

**Additivity** (declared per metric, catalog `0.5`, matching `bench/metrics.yaml`'s own anchors):
- `formal_checks_clean` — **additive** (0/1 indicator).
- `statement_integrity` — **additive** (0/1 indicator).
- `model_conformance` — **non-additive** (ratio, `traces_accepted / traces`).
- `model_non_vacuity` — **non-additive** (ratio, `variants_rejected / variants`).
- `bugs_confirmed` — **additive** (0/1 today; `simplify:` ceiling is exactly one seeded bug per G-task, matching `formal.seeded_bugs: 1` in both stubs; upgrade trigger: a task version with `seeded_bugs > 1`, at which point it becomes a count and the catalog anchor changes with a version bump, per US-4).
- `bug_claim_precision` — **non-additive** (ratio, `confirmed / claimed`).

**History rule.** No attribute here has a "meaning of a past record" to rewrite — a score row is never rewritten (row-16's rule, unchanged). `formal.statement_hash` in `task.yaml` is Type-2 by the existing tasks-freeze mechanism: a task version is a whole-file content hash (`task_version_hash`), so an edited given-statement file is a **new task version**, and the plan's frozen `task_version` (row 16 `current` check) already makes every `reads_task` grader NA `task changed since the plan` against it — this design's own `statement_hash` check is a **second, independent** integrity signal, scoped to the given-statement bytes specifically (see Contracts), because a task version can also change for an unrelated reason (a fixed typo in `prompt.md`) without the given statements moving; conflating the two would make `statement_integrity` fire on changes it isn't about.

**Derive, don't store.** Nothing here is a materialized derivation over other stored facts (unlike `cost_usd` or the process metrics) — every one of the six values is computed straight from the archive and the oracle assets, once, per pass. There is no rebuildable-cache obligation.

## Patterns (named and justified)

- **Strategy via the existing registry** (`GRADERS["formal"]`), Pluggable Selector — reused, not reinvented (row 16's pattern).
- **Special Case for NA** (`Score(None, reason)`) — reused; the statement-integrity cascade (below) is expressed entirely as NA reasons, no new sentinel.
- **Gateway (PoEAA), narrowed to one caller** (`correctness.run_step`) for every external toolchain invocation (TLC, `lake`) — this **is** the D3 import-lint boundary (G6), not a new pattern; named here so it appears in code as `# Pattern: Gateway via correctness.run_step (D3, R-60 allowlist)`.
- **Golden master (characterization) for the G1 reference model** — US-32's own acceptance clause ("the reference model, graded as a cell, passes and the seeded variant fails") is exactly row 16's golden-master idiom for D1/C1, applied to G1, and is backed by two named whole-cell tests in the Test plan (`test_g1_reference_cell_all_scores`, `test_g1_seeded_variant_cell_fails_non_vacuity`), not merely asserted here (revision 2, Test Architect Blocker 1) — both run against the `_replay` stub until DR-FM1's spike lands, and against the real mechanism afterward.
- **Solution-Selection Ladder, climbed:**
  - YAGNI: no new hashing recipe (reuse `plan.file_hash`/`tree_hash`, G12); no new evidence-string grammar (reuse the existing `:line` suffix, Telemetry section); no new ledger fact; no new HB-GRD error code.
  - Reuse: `correctness.run_step` for every subprocess; `plan.file_hash` for G1's statement hash; `coord-core.fold`'s own event-replay shape as the conceptual model for trace conformance (G9) — the grader does not reimplement the fold, it replays recorded *outputs* of that fold against the agent's model.
  - stdlib: `hashlib`, `re` (Lean signature extraction), `subprocess` only inside `procs.py` (never here).
  - The one genuinely new external mechanism (TLC trace validation) is named, not built, and gated behind a spike (DR-FM1) — the ladder's rung-5 "Gratuitous-Dependency gate" is not climbed past without that evidence.

## Metric definitions

**Shared NA reasons** (every metric of this grader, in addition to row 16's shared set — `task changed since the plan`, `no working copy in the archive`, `HB-GRD-002 grading step timeout after <n> s`, `HB-GRD-003 grader formal failed: <ExceptionType>`, `not built`):
- `formal toolchain not warmed: <reason>` (the jar/toolchain warm-before-clock contract, below, was not satisfied — never a silent download inside the timed step).
- `given statements edited (statement_hash mismatch)` — the cascade reason for every metric downstream of `statement_integrity` when it is 0.

### `statement_integrity` — score · additive (0/1) · both G1 and G2

**Definition.**
- **G1:** `1` iff `plan.file_hash(ws / "spec" / "Properties.tla") == task["formal"]["statement_hash"]`. `spec/Properties.tla` is the given, frozen safety/liveness-properties module; the agent's own model lives in `spec/Model.tla` (`EXTENDS Properties`) and is never hashed here.
- **G2:** `1` iff a single combined hash equals `task["formal"]["statement_hash"]`, computed as `plan.tree_hash`-shaped over three real, materialized entries, in this fixed order — **no hand-rolled text parsing** (revision 2, Simplifier finding): (a) `Proofs/Fold.lean` full bytes; (b) `lakefile.toml` and `lean-toolchain` full bytes — both are **task-owned and frozen**, not part of the agent's writable surface (the STRIDE table's "unpinned dependency" row, below); the manifest is declarative TOML per the S-12 spike, never `lakefile.lean` (the Turing-complete DSL), so it cannot itself run agent code; (c) for every name in `task["formal"]["theorem_names"]`, the **Lean elaborator's own canonical rendering of that declaration's type** — `<ELAN_HOME>/bin/lake.exe env lean <check-script>.lean` (**Verified, implementation correction**: not `--run` — `lake env lean --run <file>` requires the file to declare `main` and errors `unknown declaration 'main'` on a `#check`-only script, even though the `#check` output is still printed first; plain `lake env lean <file>.lean` elaborates the file and exits 0 with only the command output on stdout, confirmed against the real toolchain during `/implement`), a grader-generated, one-line-per-name `#check <name>` script run against `Proofs/Statements.lean` **after a `lake build` of a disposable copy** (the elaborator's import resolution needs the project's `.olean`s already built — also confirmed during `/implement`, not stated in revision 2), its output captured as text and hashed, never extracted by regex. This reuses the exact toolchain call `formal_checks_clean`'s axiom check already makes (one more `lean` invocation), so the agent's proof term after `:=` never affects the hash (elaboration reports the *type*, never the term) and there is no "top-level `:=`" ambiguity to define, because Lean's own parser — not a bespoke one — decides where the type ends. A theorem name in `formal.theorem_names` absent from `Proofs/Statements.lean` fails the `#check` step, itself a hash mismatch, never silently skipped.
- Rung: **analysis** (G1: a deterministic diff-by-hash) / **analysis via one elaborator call** (G2 clause (c): still deterministic, not a proof run).
- NA reasons: `no working copy in the archive`; **G2 only:** `formal.theorem_names not recorded for this task version` (a task-authoring gap, G13 — not this task's fault, but a real NA until the field is added); `formal.statements: agent — statement integrity not applicable` (defensive: both task stubs are `statements: fixed` today, but `config.py:297` also accepts `formal.statements: "agent"`; a future task version that sets it reads NA here — built only for a fixed given statement — rather than silently comparing against nothing).
- **Cascade (US-32), exact scope per task type** (revision 2: the hedge below is now a table, not a parenthetical):

  | Task | Cascades to NA on `statement_integrity = 0` |
  | --- | --- |
  | G1 | `formal_checks_clean`, `model_conformance`, `model_non_vacuity` |
  | G2 | `formal_checks_clean`, `model_non_vacuity` (`model_conformance` is already NA on every G2 cell regardless — its own row, below) |

  `bugs_confirmed`/`bug_claim_precision` (G1 only) do **not** cascade: a bug claim is confirmed by running the agent's named test against the real, unmodified `coord-core.py` fold and the seed's reference fix — neither reads `spec/Properties.tla` — so an edited property file has no bearing on whether a reported bug reproduces.
- Fixtures: the G1/G2 reference (once authored) → `1`. **Seeded:** one byte flipped in `Properties.tla` (G1) → `0`, cascade fires on the three G1 metrics, `bugs_confirmed`/`bug_claim_precision` on the **same cell** unaffected (the positive control proving the non-cascading pair really doesn't cascade); a byte flipped in `lakefile.toml` (G2, e.g. an added `[[require]]`) → `0`, cascade fires; a theorem's stated type edited in `Statements.lean` (G2) → `0` (the `#check` rendering differs), cascade fires; a theorem's proof term rewritten, signature untouched (G2) → `1` (the positive control proving the recipe ignores proof bodies, backed by Lean's own elaboration, not a regex); **G1 positive control:** `spec/Model.tla` changed, `spec/Properties.tla` byte-identical → `1` (proves the hash never reacts to the agent's own model).

## Toolchain invocation (closes S-12's warm-before-clock gap)

**Contract, both tools:** a direct process create through `correctness.run_step` (never `cmd.exe`, G6/G10), forward-slash absolute paths, `cwd` set to the directory the tool needs (TLC: the directory holding `.tla`/`.cfg`, G8; `lake`: the lake project root), `env` set from `correctness._env()`'s existing `HOST_ENV` allowlist (`correctness.py:96-98`) — never the raw process environment — with `TLA_LIBRARY` (TLC's module-search-path override) and `LEAN_PATH` explicitly excluded from whatever is passed through (revision 2, Security & Identity Architect Minor), so the STRIDE table's "the resolution path is grader-controlled" claim holds of the whole path, not `cwd` alone. **Before either tool is invoked, the working tree is scanned for out-of-place artifacts** (revision 2, Security & Identity Architect Blocker): `spec/**` (G1) may hold only `.tla`/`.cfg`/`.tex`; `Proofs/**` (G2) may hold only `.lean`/`lakefile.toml`/`lean-toolchain`/`.gitignore`. A hit is `formal_checks_clean = 0` before any process spawns — closing TLC's own documented operator-override mechanism (a same-named `.class` file beside a `.tla` module runs as JVM bytecode *inside* the checking process, able to read the hidden oracle assets and forge a clean result) and any analogous binary smuggling on the Lean side.

**Warm-before-clock (the S-12 fix).**
- **TLA+ jar.** The grading step never downloads `tla2tools.jar`. A shared, host-level cache path — `os.environ.get("HB_TLA_JAR") or (Path(os.environ["LOCALAPPDATA"]) / "harness-bench" / "tools" / f"tla2tools-{TLA_VERSION}.jar")` (adopted directly into this design; formerly a decision request, folded into the body — revision 2, Simplifier Minor 2 — the Owner may override `HB_TLA_JAR`/the cache root before host setup) — is resolved and sha256-verified **once, at `grading.started`** (alongside `tool_versions()`'s other measurements, row 16), recorded as `tool_versions["tla2tools"] = "<version> <sha256>"` or `"not recorded"`. If the file is absent or its digest is wrong at pass start, **every** G1 cell in the pass gets `formal_checks_clean = NA "formal toolchain not warmed: <reason>"` for that pass — never a mid-grade download, never a silent re-fetch. Warming (downloading once, matching `check_models.py`'s existing `JAR_URL`/`JAR_SHA256` pin) is a host-setup step, owned by the Leader, run before any grading pass, outside the HB-GRD-002 timeout.
- **Lean/elan toolchain.** Already host-level and warm per S-12 (G7): `~/.elan/toolchains/leanprover--lean4---v4.34.1`, 3.1 GB, outside every working copy. The grading step resolves `ELAN_HOME` once at pass start (`os.environ.get("ELAN_HOME") or Path.home() / ".elan"`) and records `tool_versions["lean"]` from `<ELAN_HOME>/bin/lake.exe --version` (measured, never guessed, the same `_version()` helper `runner.py` already has for `dotnet`). A pass on a host where the pinned toolchain was never installed gets the same `not warmed` NA — `lake build`'s own first-run behavior (install-then-build, 54 s per S-12) is exactly the network-call-inside-the-budget failure mode this rule prevents.
- **Project build output** (`Proofs/.lake/build`, 70 KB per S-12): built inside the graded step, no warming needed — it is small, local, and part of what is graded.

## Error and concurrency model

- **Concurrency unchanged** from row 16: one pass holds `grade.lock`; `formal.grade_cell` runs sequentially like every grader, one cell at a time.
- **Errors:** a grader exception is NA `HB-GRD-003 grader formal failed: <ExceptionType>` (row 16's existing rule) and the pass continues; a timeout inside `run_step` is `HB-GRD-002`; a completeness mismatch is `HB-GRD-004`. No new error code is introduced — `formal toolchain not warmed` and `given statements edited` are NA **reasons**, not pass-level error codes, matching the closed-vocabulary convention (row 16 "Reasons are deterministic").
- **The archive stays immutable.** `formal.py` reads `inp.archive / "ws"` directly for the hash checks (read-only) and runs the toolchains inside `out_dir` (never inside `archive`), exactly as `correctness.grading_copy` already isolates build output from the archive.
