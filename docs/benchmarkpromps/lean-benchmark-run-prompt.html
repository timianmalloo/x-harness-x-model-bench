Prompt 1: run the lean benchmark for this CLI

Nothing to fill in. The CLI you paste into works out what it is (harness, model, effort, context window) from its own configuration, names the run itself, and runs both arms: pack off and pack on. It ends with an HTML run summary open in Chrome and one HANDOFF: line for Prompt 2.

How to use it

  1. Set the CLI up the way you want it measured: the model, effort and context window (/model, or the CLI's config file). The run measures exactly that.
  2. Open a new session of that CLI in C:\Projects\x-harness-x-model-bench, with full permissions so it runs unattended. Click Copy prompt below and paste it in.
  3. Its first line names the run: RUN: <RUN_ID> | harness … | model … | effort … | context …. Its last line is HANDOFF: <RUN_ID>@<worktree>. Paste that line into Prompt 2.

You can run several CLIs at once. Each run gets its own name, branch, worktree and cell folder. Grok and agy still run one cell at a time.

How a run is named

RUN_ID = lean-<UTC yyyymmddThhmmss>-<4 random hex>-<COMBO_ID>, where COMBO_ID = <harness>-<model>-<effort>-<context>. Example: lean-20261013T214502-7c1e-claude-code-claude-opus-5-5-high-1m.

The time and the random part come first because the worktree folder keeps only the first 48 characters of the branch name. Two CLIs started in the same second still get different names.

STEP 1 - start state and the worktree (stop and report if a check fails)
  - In REPO: `git pull --ff-only origin main` succeeds. Another CLI may be pulling at the same moment: on a git lock
    error, wait 10 s and retry once. Local changes that block the pull are a stop; never stash or reset them.
    Record `git rev-parse HEAD` as BASE.
  - `python docs/ai-forward-pack/scripts/coord-core.py worktree new --branch bench/<RUN_ID> --session <RUN_ID>`
  - Read its path from `git worktree list` (call it WT). Do every later step inside WT, with absolute paths.
    Never write the main checkout after this step.

STEP 2 - the pinned builds (inside WT)
  - `uv run bench tools install --vendored C:\Users\malla\.harness-bench\agy-1.3.3\agy.exe`
  - `uv run bench tools install`
  - The output lists one line per harness with its version and sha. Check HARNESS's line is present.

STEP 3 - the environment for the cells (only HARNESS's line applies)
  - Always: unset XAI_API_KEY.
  - grok: HB_GROK_CRED_HOME=C:\Users\malla\.harness-bench\grok-cred (the bench Grok login; never ~/.grok).
  - claude-code: HB_CLAUDE_OAUTH_TOKEN = the contents of C:\Users\malla\.harness-bench\claude-oauth-token.txt.txt,
    whitespace stripped. Never print the token; pass it only in the environment of the bench commands.
  - copilot: nothing (the profile sets COPILOT_AUTO_UPDATE=false and runs copilot -p behind the local adapter).
  - agy: nothing (the profile disables its auto-update and seeds its permissions).

STEP 4 - the matrix (inside WT; write it to WT\runs\<RUN_ID>.matrix.yaml, which git ignores)
  schema: bench-matrix/3
  ring: {tag: lean}
  bom: {file: bench/bom.yaml, subset: [<TASKS>]}
  repetitions: <REPETITIONS>
  harness_parallelism: {grok: 1, agy: 1}

  comparisons: [["off", "on"]]
  combos:
    - {id: <COMBO_ID>, harness: <HARNESS>, model: "<MODEL>", effort: <EFFORT>, context: <CONTEXT>}

STEP 5 - plan, then confirm (inside WT, with the STEP 3 environment)
  - `BENCH plan --matrix runs/<RUN_ID>.matrix.yaml --run-id <RUN_ID> --parallelism <PARALLELISM>
    --arm on=<PACK>` and read the table: every cell has HARNESS's pinned build, the
    pack-on arm shows the pack revision, the pack-off arm shows "no pack", and there are 60 cells. A refusal
    (HB-PRE-*) is a stop: report it verbatim.
  - Then the same command with `--confirm`.

STEP 6 - run (inside WT)
  - `BENCH run <RUN_ID>`, as a background job. It launches the cells and runs a deterministic grading pass at its
    end. Watch it with `BENCH status <RUN_ID>` every 10 minutes; report each
    check in one line (cells ended / running / validity counts).
  - Early check: when the first 2 cells have ended, look at `BENCH status`. A cell with validity code HB-VAL-002
    (model mismatch) or HB-VAL-010 (served effort or context differs from the pin) means the harness did not serve
    what STEP 0 read: stop the run (`BENCH stop <RUN_ID>`) and report which. HB-VAL-011 (setting not recorded) is
    a warning, expected for agy's context.
  - Stop rules: the engine reports it is down twice; the host becomes unstable (record the evidence first); an
    authentication failure pauses launches (HB-CELL-202) and the decision times out. Never edit a log or a run file.

STEP 7 - verify (inside WT)
  - `BENCH verify <RUN_ID>` must exit 0. Exit 5 is an integrity failure: report it, do not repair it.

STEP 8 - the run summary (inside WT)
  - `BENCH report <RUN_ID>` (writes runs/<RUN_ID>/report.html).
  - Write runs/<RUN_ID>/run-summary.md from `BENCH status <RUN_ID> --json` and the report: the STEP 0 values
    with the file and key each came from; the FIXED block; BASE and WT; the plan's builds; cells by outcome and by
    validity (codes named); the served settings read back per arm (model, effort, context) with their source;
    tokens per cell by arm (mean, min, max; fresh input, cache read, cache write, output, reasoning); wall minutes
    per cell by arm; every warning code with its count; the run's start and end time and its total wall time. Every
    number comes from the bench's output; label anything you computed (a mean) as computed.
  - `python docs/ai-forward-pack/scripts/render-markdown.py runs/<RUN_ID>/run-summary.md --open` (HTML beside it,
    opened in Chrome). If it prints "not opened: <why>", say why.

  - Leave the worktree in place (Prompt 2 reads the run from it). Do not commit the run (runs/ is git-ignored) and

  - Report: one table (step, result, evidence) and anything that did not go as written. Then print, as the last
