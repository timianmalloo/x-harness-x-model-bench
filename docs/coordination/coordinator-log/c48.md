## CR48-1. The WinError 32: a code defect (WIN-A, delete shape)

**The code path, read at `5b45d1e2`.** `property._run_check` (`grade/property.py:474-502`) runs the check with `cwd=run` (`work/property/check-run`). The `alone_check.py` fixture in `raw` mode starts a detached `time.sleep(120)` child, which inherits that cwd. `run_check` ends with `cp.terminate_and_confirm(30)`, and its result is ignored (`:330`). Then `cp.close()`, and in `finally` `_changes.remove_tree(run)`, which is `shutil.rmtree(onexc=force)`; `force` delegates to `atomic.make_writable`. `make_writable` (`atomic.py:306-310`) does a chmod and then re-calls `func(path)` **once, at once**. The rest of `atomic.py` does handle Windows refusals: `rename_with_retry` (`:241-261`) retries `PermissionError` on `RENAME_BACKOFF = (0.05, 0.1, 0.2, 0.4, 0.8, None)`, and so does WIN-A's `_land`. The cleanup has no such retry.

**Evidence (measured):**
1. The failing run's tree is still on disk: `%TEMP%\pytest-of-malla\pytest-34033\popen-gw1\test_not_alone_at_arrival_is_r0`. `work\property\check-run` exists and is **empty**. rmtree deleted every child, and the final `rmdir` of the check's working directory was refused. That is a directory handle held by a process, not a scanner holding a file.
2. Repro 1a: a child whose cwd is the folder makes `shutil.rmtree(d, onexc=make_writable)` raise `PermissionError winerror=32`, and it leaves `d` present with no children. That is the same leftover. After `child.kill()` and `child.wait()`, the first `rmdir` **still failed**; it succeeded 10 ms later. So even an idle host has a window after the process exits in which its cwd handle is still open. Under `-n 4` load that window is longer (Inferred).
3. Repro 1b: a file handle closed 0.3 s later. `rmtree(onexc=make_writable)` raises WinError 32 today, because the callback never waits.

**Ruling CR48-1:** a code defect, not a test defect. `make_writable` retries `func(path)` on `PermissionError` with the module's own `RENAME_BACKOFF` (about 1.55 s in total), then re-raises. All ten `rmtree(onexc=make_writable)` sites inherit the fix (the sweep is in the register). Red first: a real cwd holder released from the patched `atomic.time.sleep`, which is deterministic and event-driven and has no timer (TIME-B safe), plus the bound checked by the recorded delays. Mutant M27. `atomic.py` is not a gate-stamp input (`tools/gate_stamp.py:4`, `:34`: `grade/**` plus errors, power, stats and verdicts), so no gate ring is needed. **Sibling finding, not in X-FLAKE:** `property.py:330` drops `terminate_and_confirm`'s result. After a kill that is not confirmed in 30 s, the cleanup runs against a live tree and the backoff cannot help. No instance shows it fired: the leftover tree and the 10 ms lag fit the window after exit.
