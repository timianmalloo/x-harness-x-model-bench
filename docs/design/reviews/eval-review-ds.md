Persona: distributed-systems-architect, Adversary Mode, T2. Hard veto on unsafe crash, ordering, idempotency or concurrency designs. Severity: blocking / major / minor. Confidence: Verified (I opened the file or ran it) / Inferred (reasoned from the text; the scenario is given).

### Seam disagreements

- **W0 §6 (discrimination record) and ADR-0016 §4 (compare on second production):** the record body contains `run_id` and `grading_id`, so the compare rule cannot hold (finding 2). Both texts are affected; the fix is in W0 §6 and the X-E design.
- **W0 §6 (`campaign.lock` in a committed folder) and ADR-0018 §11(b) (`git status --porcelain bench/campaigns`):** the two never meet in `.gitignore:33` (finding 7).
- **W0 §5/§6 (`plan.campaign.prereg_hash`) and ADR-0016 §3 (freeze):** no stated order between attach, launch and re-register (finding 1). Touches W1-A (plan field), W1-C (ledger), W1-D (launch recheck).

### Residual risk

Power loss between the file fsyncs and the rename stays flagged (spike E1-S1 "Still Flagged"). In-process tampering of the check is accepted by ADR-0010/0012/0013. The hard-link (`os.link`) path on a non-NTFS or network volume is untested; W1-B should state a hard failure, not a silent fallback.
