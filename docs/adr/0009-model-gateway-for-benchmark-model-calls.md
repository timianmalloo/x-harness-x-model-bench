# ADR-0009: The benchmark's own model calls go through one tool-less model gateway

- **Status:** Proposed
- **Date:** 2026-09-23 (revised after council round 1)
- **Deciders:** @timianmalloo; authored by Claude Code for the architect council
- **Context spec/architecture:** `docs/specs/harness-bench.md` US-26, US-31, US-35, US-42, US-46, US-47

## Context

The proposal ran judges "through Claude Code and Codex". A coding harness gives its model tools, which the security gate forbade for anything that reads agent-written text (US-46). Grading must be reproducible from cache (US-26). There are no vendor API keys on the workstation today.

## Decision

All benchmark-originated model calls go through one **model gateway**, `judge(item) → verdict`, `summarize(manifest) → claims`, `match(question) → decision`. This is the AI Gateway pattern with Read-Through / Cache-Aside on exact keys, plus the Guardrail Filter (LOA 6.2). The gateway:
- takes typed inputs;
- sends agent-derived text only inside delimited data blocks;
- requests schema-constrained output and validates it;
- reads through the shared content-addressed verdict cache (ADR-0006), so a cache hit is a lookup of an existing entry;
- sends every payload through the egress gate (ADR-0005) first;
- writes its own usage as `model_calls` rows with principal `gateway`.

**One backend, chosen by the owner before phase 3.** Either vendor APIs (Anthropic Messages, OpenAI Responses, no tools declared), or each vendor's CLI in print/exec mode inside a cell-style container with an empty home and every tool denied. Only the chosen backend is built. The headless option qualifies only if the US-46 fixture that asks the model to run a command produces no tool call. **If the backend is unavailable, the result is NOT_RECORDED.** There is no fallback. The run header names the backend.

**The AI summaries are generated by `bench report`** through the gateway, not by the coordinator session (ADR-0007).

**Tier allocation (LOA P1):**
- Judges: T3+, the most capable model per vendor, pinned. The two vendors form an independent jury (Self-Consistency across providers, LOA 3.5), with the calibration set as the verifier.
- Summaries: T3.
- Matcher: T0 exact or normalised match first. In phase 2 that is the only rung; a miss sends the default reply and is recorded. The T2/T3 rung arrives with the gateway in phase 3.

**Cost model** [Inferred; replaced by measured values after the smoke run]:
- Per judged item: one call per judge, at most a few thousand input tokens (rubric + artifact excerpt + oracle).
- Per grid run: judged metrics × cells × 2 judges, less cache hits.
- The gateway enforces the run's spend cap (US-15) and records its spend as coordinator overhead (US-17).

## Alternatives considered

- **Judges as full harness sessions (the proposal):** rejected. Tools plus untrusted text is the injection path the security gate closed.
- **Graders calling vendors directly:** rejected. The cache, scan, schema and blinding would be re-implemented per grader and would drift.
- **Two backends with automatic fallback:** rejected. It designs two implementations before either is chosen, and a silent backend switch changes the judge.

## Consequences

- **Positive:**
  - Tool-less and schema-bound by construction.
  - Re-grades are free and deterministic.
  - Blinding (US-35) and scanning (US-47) are enforced in one place.
- **Negative / accepted trade-offs:**
  - Phases 3 and 4 wait on the owner's backend choice.
  - A subscription-backed headless judge carries account context, which is recorded.
- **Follow-ups / new risks:**
  - The owner decides on API keys versus the headless backend.
  - Spike the chosen backend with the US-46 fixture.
