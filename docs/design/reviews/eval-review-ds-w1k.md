# W1-K: Distributed Systems lens review (rv-ds-w1k-e1e4, 2026-10-03)

Persona: distributed-systems-architect, Adversary Mode, T2, hard veto. Read: `docs/design/eval-resume.md` (all), `models/run_lifecycle.tla` (grep of ApplyStop, Resume, GradeStart, Fairness), R-100 and R-101 (`docs/notes/rulings.md`), `engine.py` 340-460, 505-530, 620-724, `oslock.py`, `workspace.py:195`, `views.py` 60-100 and 530-545, `status.py:123`, `cli.py` 180-290. Severity: blocking / major / minor. Confidence: Verified (opened) / Inferred.

**F-1 under R-101 (the ordering consequence).** Before R-101 the finish-the-stop resume wrote no `run.completed` and no grading pass. That would have left: (1) the C7 cells (never launched, no outcome, by design) pending forever, so `HB-ALM-001` would fire every 15 minutes on a free lock, against the design's and R-100 condition 6's claim that "no cell is pending" (alarm pending = plan cells with no `cell.outcome`, s6.2); (2) the resume's engine segments unsealed, with no `segment_heads` pin, so a tail cut after the fact verifies; (3) `status` "incomplete" for a run the live path reports "complete" (`status.py:125`). R-101 (the live tail: drain, grade, `run.completed`, seal, exit 3; `engine.py:412-426`, `ended_whole` ignores `run_stopped`) removes all three: `run.completed` follows the last `run.resumed`, D-K5 stays the one reader, the alarm is silent by the record, and the model and code agree with no exception. I judge R-101 correct on ordering. The design does not yet say it (finding 1a). (Verified: code and rulings)

## Seam disagreements (E2E-D)

- `eval-resume.md` s3.1 steps 4 and 8, s4 W12/W12e and M-STOPGRADES, s5.3, s9, s12 F-1 row vs R-101 conditions 1-4 and W0 s11 `HB-RUN-008`: the design still says "no `run.completed`, no grading pass" and the HB-RUN-008 line without "graded".
- `eval-resume.md` s6.2 ("after a finish-the-stop resume no cell is pending") vs s3.2 C7 ("no action", cell stays unrecorded): true only through `run.completed`, not through the pending set (finding 1b).

## Items checked and held

- **Three stop windows and finish-the-stop.** The predicate (D-K4) matches the append order in `_read_controls` and `_apply_resolution` (Verified). Every crash between `control.applied`, `decision.resolved` and `run.stopped` leaves a state the classifier maps to `stopped`; the idempotent re-run works once 1a and 1b are applied.
- **NoLaunchAfterStop.** The model flag is set by `WriteIntent` and `StartCell`; `Resume` has no guard; `launch_after_stop` and `stop_resume_launches` are rejected per the design's TLC record. I did not rerun TLC (Inferred from the record).
- **Relaunch of a never-prompted cell.** Discard before the second intent is correct and required (`workspace.py:195`, Verified). The prompt barrier is real (`cell.prompt_sent` fsynced before the write, `engine.py:7, 714`), so "no `prompt_sent`" means no prompt reached the agent (Verified).
- **"Completed" after the last `run.resumed`.** Correct and, with R-101, the only reader.
- **Heartbeat-age refusal.** Sound: the lock holds no PID, the lock file's mtime is readable under a mandatory byte lock (`oslock.py:52-61`), and the OS frees the lock on death. Finding 3 is the only gap.
- **Unnamed Job Object and the `os.kill(pid, 0)` ban.** Correct reading of `procs.py:216-220`; `OpenProcess(SYNCHRONIZE)` with a zero-timeout wait is the right primitive. Finding 4 adds the creation-time guard.
- **`recover_archive`.** The state machine is right; finding 6 moves one check.
